Cloud Services Assignment

This webpage documents my work for the cloud services assignment. The webpage is deployed using CSC Rahti.

1. Describe reasons why so many (most?) companies are using cloud based email and calendar services

Many companies use cloud email and calendars because they are easier to manage than running their own servers. The cloud provider handles the servers, maintenance and updates. Employees can access their email and calendar from different devices and locations. It is also easy to add or remove users when the company grows. Microsoft Exchange Online, for example, provides hosted email and calendar services for businesses.

2. What would a mid-size company store to the Amazon Glacier? What not? Why? What other large cloud backup or mass storage providers are there?

A mid-size company could use Amazon S3 Glacier for old backups, archived documents and other data that does not need to be accessed often. It is not a good choice for files that are needed every day because some Glacier storage classes require the data to be restored before it can be accessed. Other cloud storage providers include Microsoft Azure Blob Storage, Google Cloud Storage, Backblaze B2 and Wasabi.

3. Select and describe 2-3 well-known Amazon S3 data leak incidents. What went wrong? List some automated S3 bucket search engines and attack tools (don't try the tools, illegal!)

In the Verizon incident, customer information was exposed because an S3 bucket used by a Verizon partner was publicly accessible. Another example is Accenture, where several S3 buckets were found publicly accessible and contained sensitive credentials and other information. Tools such as GrayhatWarfare and S3Scanner can be used to find exposed storage, but they should only be used for authorized security testing.

4. Compare few cloud data storage provider features and pricing (either for home users or for enterprises)

Microsoft OneDrive gives 5 GB for free. Its Microsoft 365 Basic plan gives 100 GB for $1.99/month, while Microsoft 365 Personal gives 1 TB for $9.99/month and also includes Office applications. Dropbox has 2 GB for free. Its Plus plan gives 2 TB for $9.99/month. Dropbox also has business plans with features such as team folders, administration and advanced security. In my opinion, Google One is good for people already using Google services, while OneDrive is useful for people who use Microsoft Office. Dropbox is more focused on file sharing and collaboration. The best choice depends on how much storage is needed and which other services the user already uses.

Week 4 - Application description

I deployed a three-container application to CSC Rahti. The application consists of a frontend, a Node.js/Express backend and a MySQL database.

The frontend communicates with the backend using a REST API. The backend connects to MySQL, writes data to the database and reads the stored data. Kubernetes Services are used for communication between the containers.

Configuration such as the database host, user and database name is stored in a ConfigMap. Database passwords are stored in a Secret. MySQL uses a PersistentVolumeClaim so that the database data is not lost when the MySQL Pod is replaced.

Week 4 - Database persistence

I tested MySQL persistence by first checking the visit count stored in the database. The count was 4. I then manually deleted the MySQL Pod from Rahti.

Kubernetes automatically created a new MySQL Pod. After the new Pod started, I opened the application again and the visit count increased to 5 instead of starting again from 1. This showed that the database data survived the Pod replacement.

The MySQL data is stored using a 1 GiB PersistentVolumeClaim called mysql-data. The storage exists separately from the MySQL Pod, so replacing the Pod does not remove the stored database data.

Week 4 - Pod recovery

I tested automatic Pod recovery by manually deleting the running backend Pod. The old backend Pod was backend-84df85fcb9-rg9zj.

After deleting it, Kubernetes automatically created a replacement Pod called backend-84df85fcb9-w2srv. The application continued working after the replacement.

This happens because the backend is managed by a Kubernetes Deployment. The Deployment keeps the requested number of backend replicas running. When a Pod is deleted, Kubernetes detects that a replica is missing and creates a new Pod.

Week 4 - Backend scaling

I tested scaling by increasing the backend Deployment from one replica to three replicas. Rahti created three running backend Pods. I then scaled the Deployment back to one replica.

The frontend does not need to know the IP addresses of the individual backend Pods. Requests to /api are routed to the backend Service, which forwards requests to the available backend Pods. This allows Pods to be added, removed or replaced without changing the frontend.

Week 4 - Application update

I tested application updates by modifying the application, building new Docker images and pushing the new image versions to Docker Hub.

The backend was updated to version 1.0.2 and the frontend was updated to version 1.0.2. I then updated the Rahti Deployments to use the new images. Kubernetes performed a rolling update and replaced the old Pods with Pods running the new versions.

The rollout status showed that the Deployments were successfully updated. This allows a new application version to be deployed without manually deleting and recreating all of the Pods.

Week 4 - Problems and solutions

One problem was that the frontend Route returned a 503 error even though the frontend container was running. I tested the Pod and Service to find the problem. I changed Apache to listen on port 8080 and configured the frontend Service to forward port 80 to port 8080. I also configured the Route to use the named HTTP Service port. After these changes, the public frontend Route worked correctly.

I also had a SQL syntax error in the backend when testing the MySQL connection. I checked the backend logs, corrected the SQL query and built a new backend image. After deploying the new image, the backend could successfully communicate with MySQL.

Week 4 - Rahti compared with Docker Compose and CPouta

In the previous assignment I used Docker Compose to run the containers on a CPouta virtual machine. In Rahti the containers are managed using Kubernetes resources such as Deployments, Services and Routes.

Rahti also makes it easier to scale the application and automatically replace failed Pods. MySQL data is stored using a PersistentVolumeClaim, so the data stays even if the database Pod is replaced.

Week 5 - Part A Questions

1. What is a Web Application Firewall (WAF)?

A Web Application Firewall protects web applications by checking HTTP traffic before it reaches the application. It can help block attacks such as SQL injection, cross-site scripting and other malicious requests.

In my Week 4 application I would place the WAF before the public Route. This means requests would be checked before they reach the frontend, backend and MySQL database.

2. What is YAML and why is it used with Kubernetes/Rahti?

YAML is a text format used for configuration files. In Kubernetes and Rahti it is used to describe resources such as Deployments, Services, Routes, ConfigMaps and PersistentVolumeClaims. I used YAML files for these resources in my Week 4 application.

YAML is similar to JSON, but it usually uses indentation instead of brackets and many quotation marks. I find YAML easier to read for Kubernetes configuration, while JSON is commonly used when applications exchange data through APIs.

3. Public APIs and my Week 4 backend

Public APIs allow an application to get information or services from another application over the internet. Some examples are weather APIs, currency exchange APIs, map APIs and public transport APIs.

A realistic addition to my Week 4 application would be a weather API. The backend could request weather information for a city and return it to the frontend as JSON. The frontend could then display the current weather together with the data from my own backend.

4. What is the difference between SAML and OAuth?

SAML is mainly used for authentication and single sign-on, especially in companies. For example, an employee could use the same company account to sign in to several different services.

OAuth is mainly used to give an application limited access to another service without giving it the user's password. It is commonly used with services such as Google or GitHub. A company could use SAML for enterprise single sign-on, while OAuth is useful when an application needs permission to access another service on behalf of a user.

Week 5 - Part B - Redis Cache

I added Redis caching to my Week 4 application. Redis runs in its own container in Rahti and the backend connects to it using a Kubernetes Service.

The backend first checks Redis for the visit count. If the value is not cached, it reads the count from MySQL and stores it in Redis for 30 seconds. The next request can then get the value from Redis instead of querying MySQL again.

I tested the cache by sending two requests to the API. The first request showed "cache_source: database" and the second request showed "cache_source: redis". This showed that the Redis cache was working.
